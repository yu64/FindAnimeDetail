# /find（アニメ検索）設計

作品名や期間から、アニメの初回放送を Annict で探すコマンド。検索語ごとに、期間内に見つかったか・放送前か・優先局で放送するかを区別して返す。

## 1. 仕様

### 入力

```text
/find #word 作品名
/find #word 作品名1, 作品名2 #season next
/find #word 作品名 #from 2027-01 #to 2027-04
/find #season 2027-winter #plain
/find #format md #word 作品名
/find #word 作品名1, 作品名2 #out #miss

/find
作品名1
作品名2
```

| パラメータ | 内容 |
| --- | --- |
| `word`（任意） | 検索語。カンマ区切り、または2行目以降に1行ずつ指定する。期間（`season`・`from`・`to`）を指定しない場合は必須 |
| `season`（任意） | 期間をシーズンで指定する。`2027-winter` 形式（`winter`・`spring`・`summer`・`autumn`）、`now`（今季）、`next`（来季）。カンマ区切りで複数指定できる |
| `from`（任意） | 期間の開始日時（含む）。`2026-10`・`2026-10-01`・`2026-10-01T00:00`・時差付きの日時を指定できる。時差がなければ日本時間。省略時は下限なし |
| `to`（任意） | 期間の終了日時（含まない）。書式は `from` と同じ。省略時は上限なし |
| `format`（任意） | `TSV`（既定）または `MD` |
| `hit`・`done`・`skip`・`out`・`miss`（任意・スイッチ） | 出力する状態。指定した状態だけを出力する。省略時は放送予定だけを出力する |
| `plain`（任意・スイッチ） | `状態`・`検索語` の列を出力しない |

### 期間

期間は、シーズン（`season`）か日時（`from`・`to`）の**どちらか一方**で指定する。両方を指定した場合はエラーとする。期間を指定しない場合は、`season` を `now, next`（今季と来季）とする。`from`・`to` には既定値を設けず、省略した側は制限なしとする。

| 指定 | 期間内の判定 |
| --- | --- |
| シーズン | 作品のシーズン（Annict の `seasonYear`・`seasonName`）が指定したシーズンのいずれかに一致する。シーズンが未設定の作品は期間外 |
| 日時 | 作品の初回放送の日時が `from` 以上・`to` 未満。初回放送の日時が分からない作品は期間外 |

- シーズンと日付の対応は Annict の作品ごとの分類で決まる（12月末に始まる冬の作品などがある）ため、シーズン指定ではシーズンを日時の範囲に換算しない。
- `now`・`next` は実行日から求める。1〜3月を winter、4〜6月を spring、7〜9月を summer、10〜12月を autumn とする。
- **結果の作品はすべて期間内に収まる。** 期間外の作品は出力しない（検索語ごとに `期間外` の1行だけを出す）。

### 状態

| 状態 | スイッチ | 条件 |
| --- | --- | --- |
| 放送予定 | `#hit` | 優先局で放送し、期間内で、初回放送が現在より後。シーズン指定で放送日時が未登録の作品も含む |
| 放送済み | `#done` | 優先局で放送し、期間内で、初回放送が現在以前 |
| 対象外 | `#skip` | 期間内だが、優先局（`ANNICT_API_CHANNEL_PRIORITY`）の放送がない |
| 期間外 | `#out` | 検索語に一致する作品はあるが、期間内のものがない |
| 未登録 | `#miss` | 検索語に一致する作品が1件もない |

- 放送予定・放送済み・対象外は1作品1行、期間外・未登録は検索語ごとに1行。
- 期間外・未登録は検索語がある場合だけ出る。
- 状態列は日本語で出力し、スイッチとの対応は `/help` に載せる。
- 既定は放送予定だけとし、結果をそのまま `/reserve` に貼り付けられるようにする。見つからなかった検索語は既定では出ないため、確認する場合は `#out`・`#miss` を指定する。

### 出力（TSV）

すべての状態（`#hit #done #skip #out #miss`）を指定した場合の例:

```text
状態	検索語	放送開始日	時刻	曜日	放送局	タイトル	公式URL
放送予定	SAKAMOTO	2027-01-10	23:00	日	テレビ東京	SAKAMOTO DAYS 第2期	https://example.com
放送済み	ぼく	2026-10-04	09:00	日	フジテレビ	僕らが選んだベストアドベンチャー	https://example.com
対象外	MyGO					BanG Dream! MyGO!!!!! // Ave Mujica	https://example.com
期間外	ワンパンマン					ワンパンマン	
未登録	わたし					わたし	
```

`#plain` を指定した場合:

```text
放送開始日	時刻	曜日	放送局	タイトル	公式URL
2027-01-10	23:00	日	テレビ東京	SAKAMOTO DAYS 第2期	https://example.com
2026-10-04	09:00	日	フジテレビ	僕らが選んだベストアドベンチャー	https://example.com
				BanG Dream! MyGO!!!!! // Ave Mujica	https://example.com
				ワンパンマン	
				わたし	
```

返信全体を1つの TSV とする。LINE で部分的にコピーしなくても、そのまま TSV として使えるように、見出し行とデータ行以外（注記・案内文）は含めない。

- 1行1タイトル。期間外・未登録の行は `タイトル` 列に検索語を出す。
- 日時・曜日は日本時間。初回放送が分かっている場合は、状態にかかわらず日時と局を出す。
- 値がない欄は空文字にする（`N/A` は使わない）。値がない理由は `状態` 列で分かる。
- 検索語なしで期間だけを指定した場合、`検索語` 列は空にする。
- 並び順は、検索語の入力順 → 状態（放送予定・放送済み・対象外・期間外・未登録）→ 放送予定・放送済みの中は日本時間の曜日（月→日）と時刻。同じ曜日・時刻は Annict の返却順。
- 外部の局名・タイトルに含まれるタブ・改行は空白に置き換える。
- 列名で `タイトル` 列を探す `/reserve` に、そのまま貼り付けられる。`#plain` で先頭の列が空の行も、パーサーが行頭のタブを残すため列はずれない。

### 出力（Markdown）

`#format md` では、状態の見出しごとに表を分け、Kitware Markdown Viewer で開く URL を返す。

- 放送予定・放送済みの表: 検索語・作品（Annict へのリンク）・初回放送・放送局・公式サイト。
- 対象外の表: 検索語・作品・初回放送・放送局。
- 期間外・未登録: 検索語の一覧。
- スイッチで指定しなかった状態の見出しは出さない。値がない欄は `—` にする。
- `#plain` を指定した場合は、表から検索語の列を省く（状態は見出しで分かる）。
- URL が 5000 文字（LINE の1メッセージ）を超える場合は、検索範囲を絞るよう案内する。

### ヘルプ（`/help find`）に記載すること

出力に注記を含めない代わりに、次をヘルプに記載する。

- 期間の指定方法（`season` と `from`・`to` はどちらか一方。省略時は今季と来季。`from`・`to` は省略した側が制限なし）と、結果はすべて期間内に収まること。
- スイッチと状態の対応（`#hit`＝放送予定、`#done`＝放送済み、`#skip`＝対象外、`#out`＝期間外、`#miss`＝未登録）と、省略時は放送予定だけを出力すること。見つからなかった検索語を確認する場合は `#out`・`#miss` を指定すること。
- 今季に始まって放送中の作品は放送済みになり、既定では出ないこと。予約する場合は `#hit #done` を指定すること。
- `#plain` で `状態`・`検索語` の列を省けること。
- 作品は検索語（期間だけの場合はシーズン）ごとに最大 50 件、作品ごとに放送データは最大 50 件までしか調べないこと。件数の多い検索語・シーズンでは、一部の作品が結果に含まれない。
- 再放送は初回放送の判定に使わないこと。
- `/reserve` に貼り付けると、すべての行が予約の対象になること。既定の出力は放送予定だけなので、そのまま貼り付けられる。

## 2. Annict への問い合わせ

Annict の API はリクエスト回数で制限されるため、**1回の `/find` につき問い合わせは1回**とする。LINE の返信の時間制限にも収まるようにする。複数の検索語や確認用の問い合わせは、エイリアスを付けて1回のリクエストにまとめる。

| 指定 | 問い合わせ | 期間の判定 |
| --- | --- | --- |
| 検索語 ＋ シーズン（期間の省略を含む） | 検索語ごとに2つ。`w{i}`: `titles` ＋ `seasons` で期間内の作品。`e{i}`: `titles` だけで1件（作品の有無の確認） | Annict が絞り込む。`w{i}` が0件で `e{i}` があれば期間外、`e{i}` も0件なら未登録 |
| 検索語 ＋ 日時 | 検索語ごとに `w{i}`: `titles` だけ | 初回放送の日時で絞り込む。`w{i}` があって期間内が0件なら期間外、`w{i}` が0件なら未登録 |
| シーズンだけ | `w0`: `seasons` だけ。視聴者数の多い順 | Annict が絞り込む |
| 日時だけ | `w0`: 期間にかかるシーズンと前後1シーズンずつの `seasons`。`to` がなければ来季まで。視聴者数の多い順。`from` がないと問い合わせるシーズンを決められないため、`from` を必須とする | 初回放送の日時で絞り込む。シーズンの境目の作品も漏らさないよう、前後のシーズンも問い合わせる |

```graphql
query SearchWorks($t0: [String!], $s: [String!]) {
  w0: searchWorks(titles: $t0, seasons: $s, first: 50) {
    nodes {
      annictId
      title
      officialSiteUrl
      seasonYear
      seasonName
      programs(first: 50, orderBy: { field: STARTED_AT, direction: ASC }) {
        nodes { startedAt rebroadcast channel { annictId name } }
      }
    }
  }
  e0: searchWorks(titles: $t0, first: 1) { nodes { annictId } }
}
```

- `titles` と `seasons` を両方指定すると AND 条件、`seasons` の複数指定は OR 条件になる。
- 検索語ごとにエイリアスを付け、検索語と作品を対応付ける。Annict は表記の揺れも拾う（「ぼく」で「僕」もヒットする）ため、返却されたタイトルから検索語を判定することはできない。
- 作品はエイリアスごとに最初の 50 件、放送データは作品ごとに最初の 50 件までとし、続きのページは取得しない。
- 放送データは局で絞り込めない（`Work.programs` には局の引数がなく、放送を直接検索する API もない）。局の判定は取得後に行う。

## 3. 初回放送の判定

1. 再放送（`rebroadcast: true`）の放送データは使わない。
2. 優先局の放送データのうち、局の優先順位が最も高い局を選び、その局の最も早い放送を初回放送とする。局の優先度は日時の有無より優先する。
3. 優先局以外と判明している局の放送は採用しない。局が不明な放送は、優先局の候補がない場合に限り使う。
4. 優先局（または局不明）の初回放送がない作品は対象外とする。日時で期間を判定する場合、対象外の作品はいずれかの局の再放送を除く最初の放送日時で期間内かを判定する。
5. 初回放送の日時と現在日時を比べて、放送予定か放送済みかを決める。

判定はすべて取得済みのデータで行い、追加の問い合わせはしない。

## 4. 構成

| 層 | クラス | 役割 |
| --- | --- | --- |
| presentation | `FindCommandDef` | パラメータを解釈して `FindInput` を作る。期間の指定の検証。ヘルプ |
| usecase | `IInput.FindInput` | 検索語・期間・形式・出力する状態 |
| usecase | `FindUsecase` | 期間・状態の判定、TSV・Markdown への整形 |
| usecase | `IAnnictClient` | 検索語・シーズンごとの作品と、判定に使う放送データ・シーズンを返すインターフェイス |
| infrastructure | `IAnnictDef` | エイリアス付きの GraphQL を1回送る Quarkus REST Client。初回放送の判定 |
| infrastructure | `AnimeSearchException` | 通信・GraphQL のエラー。アクセス制限（HTTP 429）を判定できる |
| config | `AnnictConfig` | URL・トークン・局の優先順位 |

## 5. エラー処理

- 検索語も期間もない場合、検索語がなく日時の期間に `from` がない場合、シーズンと日時を両方指定した場合、シーズンの書式が不正な場合、`from` が `to` 以降の場合は、入力エラーとして案内する。
- Annict のアクセス制限（HTTP 429）は、時間を置いて再検索するよう案内する。
- そのほかの通信・応答の異常は、詳細を返信に含めずに失敗を案内する（詳細はログにだけ残す）。
- GraphQL は HTTP 200 でも `errors` を返すことがあるため、`errors` があれば失敗として扱う。
