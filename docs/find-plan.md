# /find（アニメ検索）設計

作品名から、これから初回放送されるアニメを Annict で探すコマンド。検索語ごとに、見つかったか・条件に合ったかを区別して返す。

## 1. 仕様

### 入力

```text
/find #word 作品名
/find #word 作品名1, 作品名2 #from 2026-10
/find #format md #word 作品名
/find #word 作品名1, 作品名2 #miss
/find #word 作品名 #hit #skip
/find #word 作品名1, 作品名2 #hit #plain

/find
作品名1
作品名2
```

| パラメータ | 内容 |
| --- | --- |
| `word`（必須） | 検索語。カンマ区切り、または2行目以降に1行ずつ指定する |
| `from`（任意） | 初回放送日時の下限（指定日時を含む）。`2026-10`・`2026-10-01`・`2026-10-01T00:00`・時差付きの日時を指定できる。時差がなければ日本時間。省略時は実行時の現在日時 |
| `format`（任意） | `TSV`（既定）または `MD` |
| `hit`・`skip`・`miss`（任意・スイッチ） | 出力する区分。指定した区分だけを出力する。省略時はすべての区分を出力する |
| `plain`（任意・スイッチ） | `状態`・`検索語`・`理由` の列を出力しない |

### 区分

検索語ごとに、作品を次の3つに分ける。

| 状態 | スイッチ | 条件 |
| --- | --- | --- |
| 放送予定 | `#hit` | 優先局での初回放送が `from` 以降 |
| 対象外 | `#skip` | 登録はあるが、条件に合わない |
| 未登録 | `#miss` | その検索語に一致する作品がない |

状態列は日本語で出力し、スイッチとの対応は `/help` に載せる。既定で一部の区分を隠すと、その区分しかない検索語が結果から消えてしまうため、既定はすべての区分とする。

対象外の理由:

| 理由 | 条件 |
| --- | --- |
| 放送済み | 優先局での初回放送が `from` より前 |
| 日時未定 | 放送データがない、または日時が不明 |
| 対象局なし | 取得した放送データに、優先局（`ANNICT_API_CHANNEL_PRIORITY`）の放送がない |

### 出力（TSV）

```text
状態	検索語	放送開始日	時刻	曜日	放送局	タイトル	公式URL	理由
放送予定	ぼく	2026-10-04	09:00	日	フジテレビ	僕らが選んだベストアドベンチャー	https://example.com	
対象外	ぼく	2004-04-01	18:00	木	テレビ東京	ぼくらの	https://example.com	放送済み
対象外	フリーレン						葬送のフリーレン 第3期	https://example.com	日時未定
未登録	わたし					わたし		
```

`#plain` を指定した場合:

```text
放送開始日	時刻	曜日	放送局	タイトル	公式URL
2026-10-04	09:00	日	フジテレビ	僕らが選んだベストアドベンチャー	https://example.com
2004-04-01	18:00	木	テレビ東京	ぼくらの	https://example.com
				葬送のフリーレン 第3期	https://example.com
				わたし	
```

返信全体を1つの TSV とする。LINE で部分的にコピーしなくても、そのまま TSV として使えるように、見出し行とデータ行以外（注記・案内文）は含めない。

- 1行1タイトル。放送予定・対象外は1作品1行、未登録は検索語ごとに1行で、`タイトル` 列に検索語を出す。日時・曜日は日本時間。
- 対象外の行は `理由` 列に理由を出す。放送済みのように初回放送が分かっている場合は、日時と局も出す。
- 値がない欄は空文字にする（`N/A` は使わない）。値がない理由は `状態`・`理由` 列で分かる。
- 並び順は、検索語の入力順 → 状態（放送予定・対象外・未登録）→ 放送予定の中は日本時間の曜日（月→日）と時刻。同じ曜日・時刻は Annict の返却順。
- 外部の局名・タイトルに含まれるタブ・改行は空白に置き換える。
- 列名で `タイトル` 列を探す `/reserve` に、そのまま貼り付けられる。`#plain` の有無で列が変わっても影響しない。

### 出力（Markdown）

`#format md` では、「放送予定」「対象外」「未登録」の見出しごとに表を分け、Kitware Markdown Viewer で開く URL を返す。

- 放送予定の表: 検索語・作品（Annict へのリンク）・初回放送・放送局・公式サイト。
- 対象外の表: 検索語・作品・初回放送・放送局・理由。
- 未登録: 検索語の一覧。
- スイッチで指定しなかった区分の見出しは出さない。値がない欄は `—` にする。
- `#plain` を指定した場合は、表から検索語・理由の列を省く（状態は見出しで分かる）。
- URL が 5000 文字（LINE の1メッセージ）を超える場合は、検索範囲を絞るよう案内する。

### ヘルプ（`/help find`）に記載すること

出力に注記を含めない代わりに、次をヘルプに記載する。

- スイッチと状態の対応（`#hit`＝放送予定、`#skip`＝対象外、`#miss`＝未登録）と、省略時はすべての区分を出力すること。
- `#plain` で `状態`・`検索語`・`理由` の列を省けること。
- 対象外の理由（放送済み・日時未定・対象局なし）の意味。
- 検索語ごとに作品は最大 50 件、作品ごとに放送データは最大 50 件までしか調べないこと。件数の多い検索語では、一部の作品が結果に含まれない。
- 再放送は初回放送の判定に使わないこと。
- `/reserve` に貼り付けると、対象外の作品と未登録の検索語も予約の対象になるため、放送予定だけを予約する場合は `#hit` で絞ること。

## 2. Annict への問い合わせ

Annict の API はリクエスト回数で制限されるため、**1回の `/find` につき問い合わせは1回**とする。LINE の返信の時間制限にも収まるようにする。

```graphql
query {
  w0: searchWorks(titles: ["検索語1"], first: 50) { ...WorkFields }
  w1: searchWorks(titles: ["検索語2"], first: 50) { ...WorkFields }
}

fragment WorkFields on WorkConnection {
  nodes {
    annictId
    title
    officialSiteUrl
    programs(first: 50, orderBy: { field: STARTED_AT, direction: ASC }) {
      nodes { startedAt rebroadcast channel { annictId name } }
    }
  }
  pageInfo { hasNextPage }
}
```

- 検索語ごとにエイリアス（`w0`、`w1`…）を付けて1回にまとめ、検索語と作品を対応付ける。Annict は表記の揺れも拾う（「ぼく」で「僕」もヒットする）ため、返却されたタイトルから検索語を判定することはできない。
- 作品は検索語ごとに最初の 50 件、放送データは作品ごとに最初の 50 件までとし、続きのページは取得しない。
- 放送データは局で絞り込めない（`Work.programs` には局の引数がなく、放送を直接検索する API もない）。局の判定は取得後に行う。

## 3. 初回放送の判定

1. 再放送（`rebroadcast: true`）の放送データは使わない。
2. 優先局の放送データのうち、局の優先順位が最も高い局を選び、その局の最も早い放送を初回放送とする。局の優先度は日時の有無より優先する。
3. 優先局以外と判明している局の放送は採用しない。局が不明な放送は、優先局の候補がない場合に限り使う。
4. 初回放送の日時と `from` を比べて、放送予定か放送済みかを決める。日時が不明なら日時未定とする。

判定はすべて取得済みのデータで行い、追加の問い合わせはしない。

## 4. 構成

| 層 | クラス | 役割 |
| --- | --- | --- |
| presentation | `FindCommandDef` | パラメータを解釈して `FindInput` を作る。ヘルプ |
| usecase | `IInput.FindInput` | 検索語・`from`・形式・出力する区分 |
| usecase | `FindUsecase` | 区分の判定、TSV・Markdown への整形 |
| usecase | `IAnnictClient` | 検索語ごとの作品と、判定に使う放送データを返すインターフェイス |
| infrastructure | `IAnnictDef` | エイリアス付きの GraphQL を1回送る Quarkus REST Client。初回放送の判定 |
| infrastructure | `AnimeSearchException` | 通信・GraphQL のエラー。アクセス制限（HTTP 429）を判定できる |
| config | `AnnictConfig` | URL・トークン・局の優先順位 |

## 5. エラー処理

- Annict のアクセス制限（HTTP 429）は、時間を置いて再検索するよう案内する。
- そのほかの通信・応答の異常は、詳細を返信に含めずに失敗を案内する（詳細はログにだけ残す）。
- GraphQL は HTTP 200 でも `errors` を返すことがあるため、`errors` があれば失敗として扱う。
