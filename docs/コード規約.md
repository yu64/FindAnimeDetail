# コード規約

書式は Spotless（Eclipse フォーマッター）で機械的に揃え、書式以外の規約はレビューで確認する。

## 書式

ツールで自動整形する。手で揃えず、次のコマンドを実行する。

```powershell
./gradlew spotlessApply   # 整形
./gradlew spotlessCheck   # 確認のみ
```

書式違反があると `./gradlew check` / `./gradlew build` は失敗する。

一括整形のコミットは `.git-blame-ignore-revs` に登録している。GitHub は自動で参照するが、ローカルの `git blame` で除外するには次を一度実行する。

```powershell
git config blame.ignoreRevsFile .git-blame-ignore-revs
```

| 項目 | 規約 |
|---|---|
| インデント | スペース2つ（main・test 共通）。タブは使わない |
| 継続行のインデント | スペース4つ（インデント2段分） |
| 波括弧 `{` | 常に同じ行（K&R）。クラス・メソッド・コンストラクタも含む |
| 1行の長さ | 120文字。超えた行はフォーマッターが折り返す |
| 手動の改行 | フォーマッターは既存の改行を結合しない。引数を1行に1つずつ並べる書き方は維持され、閉じ括弧は最後の引数と同じ行（`… lastArg) {`）になる |
| 制御文の括弧 | キーワードの後にスペースを入れない（`if(`、`for(`、`while(`、`switch(`、`catch(`） |
| テキストブロック | 中身のインデントは変更しない |
| 空行 | 連続する空行は2行まで |
| 改行コード | LF（`.bat` / `.cmd` のみ CRLF）。`.gitattributes` で固定 |
| 文字コード | UTF-8 |
| コメント | フォーマッターはコメントを整形しない（日本語の Javadoc を折り返さないため） |

設定ファイル:

- `.editorconfig`: エディター共通の設定
- `.vscode/eclipse-formatter.xml`: Java の整形ルール。VS Code（`.vscode/settings.json` の `java.format.settings.url`）と Eclipse にも読み込める
- `build-logic/eclipse_setting/src/eclipse_format_setting.gradle`: Spotless で Eclipse フォーマッターを適用する Gradle プラグイン

## 命名

| 対象 | 規約 | 例 |
|---|---|---|
| インターフェース | 先頭に `I` | `ILineClient`, `IResult` |
| REST Client 定義 | `I…Def`。注入用の `DiRelay` を入れ子で持つ | `ILineClientDef`, `IAnnictDef` |
| ユースケース | `…Usecase` | `FindUsecase` |
| ユースケースの入力 | `IInput` 内の record `…Input` | `FindInput` |
| コマンド定義 | `…CommandDef`（`ICommandDef` を実装） | `FindCommandDef` |
| テストクラス | `…Test` | `IAnnictDefTest` |
| テストメソッド | 英語 camelCase で振る舞いを文にする | `rejectsHttpErrors` |

## パッケージと設計

- レイヤーでパッケージを分ける: `app.presentation` / `app.usecase` / `app.infrastructure` / `app.config` / `app.util`
- presentation・usecase 側にインターフェースを置き、infrastructure 側で実装する（`ILineClient` ← `ILineClientDef`）。
- DI はコンストラクタ注入（`@Inject` + `@ApplicationScoped`）。フィールドは `private final`、参照時は `this.` を付ける。
- 入力の解析エラーなど想定内の失敗は例外ではなく `IResult`（`Ok` / `Err`）で返し、`instanceof IResult.Err` で早期 return する。
- Java 25 の機能（sealed interface、record、パターンマッチの `switch`、テキストブロック）を積極的に使う。
- 設定値は `@ConfigMapping` のインターフェースで受け取り、`@WithDefault` に開発用のダミー値を置く。

## コメント

- 日本語で書く。Javadoc は1行の `/** … */` を基本とする。
- 処理のまとまりには見出しを付ける。

  ```java
  // ###########################################################################
  // MARK: 変換
  ```

- 「何をするか」より「なぜそうするか」を書く。

## テスト

- JUnit 5。テストクラスは package-private。
- モックライブラリは使わず、ラムダや自作の `Stub` クラスで差し替える。
- テスト用の値は `test-token` のように `test-` を付けたダミー値にする。

## コミットメッセージ

日本語で、何をしたかを短く書く（例: 「LineとAnnictの接続を確認」）。
